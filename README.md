# DevArt Utils

Joomla 6 administrator suite for cache control, Cloudflare integration, Google
Analytics 4 dashboards, diagnostics, and built-in administrator tools.

**Current product version:** 1.3.3 (`pkg_devartutils`)

## Purpose

DevArt Utils is the original DevArt Joomla extension. The suite package provides:

- `com_devartutils` — Cache, Cloudflare, GA4, Settings, and Tools hub
- `com_devarttools` — Administrator Tools hub (diagnostics, root text files)
- `com_devartfavicon` — Favicon Creator (accessed via Tools)
- `com_devartassetrepair` — Asset Table Repair (accessed via Tools)
- `plg_system_devartcache` — frontend cache header control
- `plg_system_devartcleancache` — administrator toolbar cache purge
- `plg_task_devartassetrepair` — Scheduled Tasks integration
- `plg_task_devarturlpurge` — Scheduled Tasks Cloudflare URL/host purge
- `plg_console_devartassetrepair` — Joomla console integration

Public download and update metadata:

https://github.com/devartgr/joomla-devart-utils

## Requirements

- Joomla 6.0+
- PHP 8.3.0+ on the web server
- PHP 8.3+ CLI for validation and build scripts

## Repository Layout

- `AGENTS.md` — shared DevArt repository standards and project-specific rules
- `PROJECT_STATUS.md` — operational milestone and verification status
- `CHANGELOG.md` — product change history
- `TEMPLATE_VERSION.md` — template version (not the product version)
- `source/` — the only development source
- `builds/` — unverified development packages generated by the build script
- `releases/` — official packages moved manually by the user
- `archive/` — structural placeholder only; historical ZIP checkpoints were moved off-repo and are not kept in the repository
- `scripts/` — shared validation and packaging infrastructure
- `docs/` — architecture, technical baseline, and bootstrap documentation
- `qa/` — Joomla installation and functional QA
- `update.xml` / `changelog.xml` — published update channel metadata (copied to repo root on build)

Generated packages are never development sources.

## Validate and Build

```shell
php scripts/validate.php
php scripts/build.php
```

The build script runs validation first, packages only declared extensions, never
overwrites an existing build, writes a SHA-256 checksum file, and publishes
`update.xml` and `changelog.xml` to the repository root.

## Documentation

- `docs/architecture.md` — repository and product architecture
- `docs/cloudflare-cache-setup.md` — **required** Cloudflare settings for HTML cache + frontend login
- `docs/current-state.md` — technical baseline and known limitations
- `docs/new-product-checklist.md` — repository initialization workflow
- `docs/jed-submission-notes.md` — JED submission notes
- `qa/checklist.md` — Joomla installation and functional QA

Cloudflare HTML edge cache and Joomla frontend login only work together when
operators configure Respect Existing Headers plus the logged-in / Remember Me
bypass Cache Rule. See `docs/cloudflare-cache-setup.md`.

## Verification

Repository validation and package generation do not constitute Joomla runtime
verification. Complete `qa/checklist.md` in a real Joomla installation before
recording the baseline as verified.
